# OpenGGF 0.6 — Release Summary

> **Status:** 0.6 prerelease / release candidate preparation

OpenGGF 0.6 is a major accuracy and tooling release for the open-source Java
engine that recreates the main Sonic the Hedgehog games from user-supplied ROM
images. This release expands playable coverage across Sonic 1, Sonic 2, and
Sonic 3 & Knuckles while strengthening the ROM-accurate physics, rendering,
audio, rewind, and trace-validation foundations needed for reliable future
development.

## Highlights

### A broader three-game engine

- Sonic 1 has broad end-to-end gameplay coverage, including title flow, special
  stages, zone events, bosses, water and drowning behavior, endings, and demo
  playback.
- Sonic 2 has extensive zone, object, badnik, boss, title, ending, special-stage,
  and level-select functionality. Casino Night's release traces are exact and
  Wing Fortress's Tornado rows match; the CPZ2 and complete-run parity
  campaigns continue with the next release.
- Sonic 3 & Knuckles has a growing playable vertical slice centered on the
  Angel Island → Hydrocity route, with substantial bring-up across later zones,
  boss scenes, bonus stages, sidekicks, and traversal objects.

### ROM-accurate gameplay and rendering

The engine now models more of the original games' behavior directly from their
disassemblies and ROM data, including:

- subpixel physics, sensors, collision, solid objects, slopes, walls, water,
  camera limits, title cards, level events, and act transitions;
- bosses, badniks, traversal objects, sidekicks, Super Sonic, character routes,
  object lifetimes, and cross-game feature donation;
- ROM-backed pattern loading, DPLC/PLC queues, Kosinski and Nemesis art paths,
  priority rendering, tilemaps, shaders, sprite batching, and foreground/background
  composition; and
- a provider-based runtime architecture that keeps game-specific rules and data
  in their owning game modules, with shared runtime-owned zone frameworks
  (`ZoneRuntimeRegistry`, `PaletteOwnershipRegistry`, `AnimatedTileChannelGraph`,
  `ZoneLayoutMutationPipeline`, `ScrollEffectComposer`,
  `SpecialRenderEffectRegistry`, `AdvancedRenderModeController`) carrying zone
  behaviour instead of zone-local state and direct manager writes.

### Data select, saves, and configuration

- S3K data select is complete: ROM-rendered save slots, team selection,
  host-owned progress, and cross-game donation so Sonic 1 and Sonic 2 can use
  the S3K presentation while keeping their own saves. Save writes go through a
  temp-file plus atomic move so an interrupted write cannot corrupt a slot.
- Runtime configuration lives in `config.yaml`; a legacy `config.json` is
  migrated automatically on first run, and the user docs describe the nested
  YAML keys.

### Audio

0.6 ships the unified audio presentation pipeline: a single PCM path through
OpenAL, presentation voices, and the capture tap that live and offline recording
share.

A further SMPS and chip-level parity programme -- retail service ordering, SFX
priority and channel ownership, pause/resume protocols, fades, regional chip
clocks, source-timed YM write scheduling, and Sonic 3 & Knuckles special-stage
and SEGA PCM behaviour -- was developed during the 0.6 cycle but is **deferred to
0.7**. It was withdrawn from this release because it produced audible
regressions that its automated coverage did not detect, and the listening
validation that would have caught them was not completed. The engine's audio
behaviour in 0.6 is therefore the pre-programme baseline. The design notes,
research artifacts, and measurement tooling remain in the repository under
`docs/architecture/` and `tools/`, so the work resumes from a complete record
rather than being re-derived.

### Gameplay-scoped rewind

Rewind now covers a substantially larger portion of live gameplay state. Dynamic
objects, recreated child graphs, riders, sidekicks, level-event state, selected
audio history, and static state adapters are captured according to explicit
ownership rules. Rewind coverage guards detect new spawnable objects, uncaptured
state, missing recreate paths, and mutable static managers that would otherwise
silently survive a restore.

### Trace replay and agent-safe development

0.6 strengthens the validation infrastructure used to compare engine behavior
against recorded hardware runs:

- BizHawk trace replay covers physics, auxiliary state, animation, dynamic art,
  hardware-timing admission, complete-run chains, and audio evidence.
- Long trace runs retain compact descriptors and only one active segment payload,
  reducing memory pressure substantially compared with eager whole-run loading.
- Builds and tests run Maven directly; each worktree owns one reusable
  `target/` tree, and every Surefire fork receives its own LWJGL extraction
  directory below `target/test-tmp`, so concurrent agent runs cannot replace one
  another's native libraries. The managed test-session coordinator developed
  earlier in the cycle was removed after it caused unbounded storage growth;
  its lifecycle research continues separately as a 0.8 ask.
- Codex and Claude workflows include ROM cross-referencing, object/boss/zone
  procedures, trace diagnosis, and worktree-local direct-Maven procedures.
- `@RequiresRom` is inherited by abstract trace bases, release CI runs the
  trace-replay profile and asserts that at least one ROM-backed trace test
  executed, and publishing the GitHub release is a manual `workflow_dispatch`
  action while the prerelease version tag is static.
- Release and architecture guards make skipped evidence, missing ROMs, invalid
  fixtures, and policy bypasses visible instead of silently weakening the
  release gate.

### Tools and editor foundations

The release carries forward mutable level layouts, profile-driven loading, ROM
offset and compression tools, audio utilities, headless test fixtures,
visual/audio regression harnesses, and contributor workflows for implementing
ROM objects and bosses. The in-engine level editor remains an experimental,
config-gated overlay prototype; it has not had active development since
2026-06-12 and is not a user-facing 0.6 feature.

## Validation status

`develop` at commit `2e06eb403` was measured on 2026-08-28 with JDK 21 and
absolute paths to the verified retail Sonic 1, Sonic 2, and Sonic 3 & Knuckles
ROMs:

- ordinary suite (`mvn test` with the three ROM properties): **14,868 tests,
  1 failure, 1 error, 18 skips** — `TestS3kCnzVisualCapture` (deterministic)
  and `TestMhzMushroomParachuteObjectInstance` (order-dependent), both under
  active repair;
- structural guards (`mvn -Dmse=off -Pguards test`): **547 tests, 0 failures,
  0 errors**;
- release trace gate (`mvn -Dmse=off -Ptrace-replay test`): **870 tests,
  6 failures, 0 errors, 7 skips**.

The six trace failures are the known-red frontier, unchanged from the
2026-08-26 no-regression baseline: S3K AIZ (frame 20713, `air`); the S3K
reference-closure fixture (frame 25589, `player_animation_id`); the S1, S2, and
S3K complete-run chains; and S2 CPZ2 segment 10 (frame 2252, `air`). Each is
recorded with its first-error frame in the
[trace frontier log](../status/trace-frontier-log.md).

Guard-profile deferrals: the frontier log's 2026-08-26 entry records a
`-Pguards` run of 557 tests with 18 failures and 1 error under the
since-removed session coordinator, but does not name the failing guard classes.
Those results are not re-verified and carry no deferral list; the guard
evidence for 0.6 is the fresh 2026-08-28 run above, which is green. No guard
class is currently deferred.

Both Maven invocations completed without heap exhaustion, fork crashes, or
LWJGL extraction collisions. The remaining automated failures are documented
parity and fixture frontiers, not hidden skips.

## Known limitations and release status

OpenGGF 0.6 is not yet a final release. The following work remains before sign-off:

- human end-to-end gameplay QA across the supported release routes;
- human audio listening QA against the intended hardware/reference behavior;
- a fresh package, ordinary-suite, guard, and trace no-regression candidate run;
  and
- correction of any release-impacting defect those checks expose.

Known gameplay and feature limitations in 0.6:

- **Game Over and Continue flow is missing in all three games.** Running out of
  lives or time stops play without the ROM's Game Over / Continue screens
  (`docs/status/known-bugs.md`, entry 1).
- **No modding framework.** An open framework for modding and customisation is a
  project goal, not a shipped feature; there is no mod-loading code in the
  engine.
- **Level editor is dormant.** Only the experimental config-gated overlay exists,
  with no development since 2026-06-12.
- **SMPS/chip-level audio parity programme deferred to 0.7** (see *Audio*
  above); the 0.6 audio path is the pre-programme baseline.
- **Sonic 3 & Knuckles is a vertical slice.** AIZ → HCZ is the primary release
  route; Flying Battery, Knuckles routes, and the S&K-half zones are outside
  release-6 trace scope. Roughly 57% of the S3K object checklist rows (134
  unique object ids) are implemented, against 122/122 for Sonic 2.

Trace policy follows
[`docs/status/trace-scope-release-6.md`](../status/trace-scope-release-6.md):
0.6 does not require every known-red in-scope trace to become green. Every
trace that passes on the candidate baseline must remain passing; a known-red
trace must not gain a new failure, regress its established frontier, or worsen
in a way attributable to the candidate; comparison, timing-authority, fixture,
and structural guards stay mandatory. Known-red Sonic 2 CPZ and Sonic 3 &
Knuckles trace/run-chain frontiers are therefore documented limitations rather
than sign-off gates, and closing them — plus functionality outside the primary
AIZ → HCZ slice — is deferred to the next release unless a frontier exposes a
confirmed real-play release defect.

The project does not ship copyrighted game assets. Users provide their own ROM
images, and runtime assets are loaded through the ROM pipeline.
