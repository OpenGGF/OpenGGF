# OpenGGF 0.6 — Release Summary

> **Status:** 0.6 prerelease / release candidate preparation

OpenGGF 0.6 is a major accuracy and tooling release for the open-source Java
engine that recreates the main Sonic the Hedgehog games from user-supplied ROM
images. This release expands playable coverage across Sonic 1, Sonic 2, and
Sonic 3 & Knuckles while strengthening the ROM-accurate physics, rendering,
audio, rewind, and trace-validation foundations needed for reliable future
development.

## Highlights

### A broader three-game engine

- Sonic 1 has broad end-to-end gameplay coverage, including title flow, special
  stages, zone events, bosses, water and drowning behavior, endings, and demo
  playback.
- Sonic 2 has extensive zone, object, badnik, boss, title, ending, special-stage,
  and level-select functionality. Casino Night's release traces are exact;
  remaining CPZ and WFZ parity campaigns continue with the next release.
- Sonic 3 & Knuckles has a growing playable vertical slice centered on the
  Angel Island → Hydrocity route, with substantial bring-up across later zones,
  boss scenes, bonus stages, sidekicks, and traversal objects.

### ROM-accurate gameplay and rendering

The engine now models more of the original games' behavior directly from their
disassemblies and ROM data, including:

- subpixel physics, sensors, collision, solid objects, slopes, walls, water,
  camera limits, title cards, level events, and act transitions;
- bosses, badniks, traversal objects, sidekicks, Super Sonic, character routes,
  object lifetimes, and cross-game feature donation;
- ROM-backed pattern loading, DPLC/PLC queues, Kosinski and Nemesis art paths,
  priority rendering, tilemaps, shaders, sprite batching, and foreground/background
  composition; and
- a provider-based runtime architecture that keeps game-specific rules and data
  in their owning game modules.

### Audio

0.6 ships the unified audio presentation pipeline: a single PCM path through
OpenAL, presentation voices, and the capture tap that live and offline recording
share.

A further SMPS and chip-level parity programme -- retail service ordering, SFX
priority and channel ownership, pause/resume protocols, fades, regional chip
clocks, source-timed YM write scheduling, and Sonic 3 & Knuckles special-stage
and SEGA PCM behaviour -- was developed during the 0.6 cycle but is **deferred to
0.7**. It was withdrawn from this release because it produced audible
regressions that its automated coverage did not detect, and the listening
validation that would have caught them was not completed. The engine's audio
behaviour in 0.6 is therefore the pre-programme baseline. The design notes,
research artifacts, and measurement tooling remain in the repository under
`docs/architecture/` and `tools/`, so the work resumes from a complete record
rather than being re-derived.

### Gameplay-scoped rewind

Rewind now covers a substantially larger portion of live gameplay state. Dynamic
objects, recreated child graphs, riders, sidekicks, level-event state, selected
audio history, and static state adapters are captured according to explicit
ownership rules. Rewind coverage guards detect new spawnable objects, uncaptured
state, missing recreate paths, and mutable static managers that would otherwise
silently survive a restore.

### Trace replay and agent-safe development

0.6 strengthens the validation infrastructure used to compare engine behavior
against recorded hardware runs:

- BizHawk trace replay covers physics, auxiliary state, animation, dynamic art,
  hardware-timing admission, complete-run chains, and audio evidence.
- Long trace runs retain compact descriptors and only one active segment payload,
  reducing memory pressure substantially compared with eager whole-run loading.
- Test reports, build outputs, temporary files, and generated artifacts are owned
  by timestamped test sessions. Each Surefire fork receives an isolated LWJGL
  extraction directory, preventing concurrent agent runs from replacing native
  libraries or contaminating one another's results.
- Codex and Claude workflows include ROM cross-referencing, object/boss/zone
  procedures, trace diagnosis, and the required sandbox/LWJGL isolation entrypoints.
- Release and architecture guards make skipped evidence, report collisions,
  missing ROMs, invalid fixtures, and policy bypasses visible instead of silently
  weakening the release gate.

### Tools and editor foundations

The release continues the editor and tooling work introduced in earlier versions,
including mutable level layouts, profile-driven loading, ROM offset and
compression tools, audio utilities, headless test fixtures, visual/audio
regression harnesses, and contributor workflows for implementing ROM objects and
bosses.

## Validation status

The current `develop` snapshot was verified on 2026-08-23 with JDK 21 and the
verified retail Sonic 1, Sonic 2, and Sonic 3 & Knuckles ROMs:

- focused Sonic 2 SCZ/Tornado verification: **32 tests, 0 failures**;
- full Sonic 2 trace class sweep: **37 tests, 5 known failures**;
- full trace profile: **868 tests, 9 failures, 0 errors, 7 skips**;
- ordinary suite: **15,046 tests, 52 failures, 9 errors, 19 skips**; and
- packaged distribution: **BUILD SUCCESS**.

The automated sessions completed without Java heap-space errors, out-of-memory
failures, fork crashes, or LWJGL extraction collisions. The remaining automated
failures are documented parity and fixture frontiers, not hidden skips.

## Known limitations and release status

OpenGGF 0.6 is not yet a final release. The following work remains before sign-off:

- human end-to-end gameplay QA across the supported release routes;
- human audio listening QA against the intended hardware/reference behavior;
- a fresh package, ordinary-suite, guard, and trace no-regression candidate run;
  and
- correction of any release-impacting defect those checks expose.

Known-red Sonic 2 CPZ/WFZ and Sonic 3 & Knuckles trace/run-chain frontiers are
documented limitations rather than 0.6 sign-off gates. Every currently green
trace remains protected, and a known-red trace may not worsen on a release
candidate. Closing the remaining parity frontiers, plus functionality outside
the primary AIZ → HCZ release slice, is deferred to the next release unless a
frontier exposes a confirmed real-play release defect.

The project does not ship copyrighted game assets. Users provide their own ROM
images, and runtime assets are loaded through the ROM pipeline.
