# OpenGGF 0.7 Roadmap

Date: 2026-08-25

Branch: `next`

Status: active roadmap for the 0.7 candidate

OpenGGF 0.7 is the complete Sonic 3 & Knuckles campaign release. Its primary
product goal is to make the locked-on game playable from Angel Island through
each character's ROM-authored finale, with the corresponding ending sequence.
The release also graduates the substantial modding, Time Attack, multiplayer,
editor, compatibility, and S3K work already staged on `next`.

This is a release roadmap, not a claim that every item named below is complete.
The status labels distinguish work already present on `next` from work that must
still satisfy its release gate.

## Release outcomes

0.7 is ready when all of the following are true:

1. Knuckles can complete his locked-on route from AIZ through the Sky Sanctuary
   finale and reach his complete outro.
2. Tails can complete his locked-on route from AIZ through Death Egg and reach
   his complete outro.
3. Sonic can complete his locked-on route from AIZ through Death Egg, enter
   Doomsday when the ROM emerald condition selects it, and reach the matching
   complete outro.
4. The three routes work without debug warps, trace-state hydration, manually
   fitted fixture constants, or game/zone carve-outs in shared runtime code.
5. Game-wide behavioral differences have a typed policy home beneath
   `GameModule`, without turning data, art, zone behavior, or runtime factories
   into a universal policy bag.
6. Existing `next` features retained for 0.7 pass their stated release gates and
   are documented honestly; unfinished optional polish remains explicitly
   deferred.

## Scope of a complete character route

The route gate follows the shipped locked-on game's character-specific
progression. A level is not complete merely because it loads or can be crossed
with debug movement.

| Character | Sonic 3 half | Sonic & Knuckles half | Finale |
|---|---|---|---|
| Knuckles | AIZ, HCZ, MGZ, CNZ, ICZ, LBZ | MHZ, FBZ, SOZ, LRZ, HPZ, SSZ | Knuckles' Sky Sanctuary/Mecha Sonic conclusion and outro; DEZ/DDZ are not part of his ROM route |
| Tails | AIZ, HCZ, MGZ, CNZ, ICZ, LBZ | MHZ, FBZ, SOZ, LRZ, HPZ, SSZ, DEZ | Tails' Death Egg conclusion and outro; DDZ is not part of his ROM route |
| Sonic | AIZ, HCZ, MGZ, CNZ, ICZ, LBZ | MHZ, FBZ, SOZ, LRZ, HPZ, SSZ, DEZ | Normal Death Egg conclusion, or DDZ and the good ending when the emerald condition selects it |

For every listed zone, completion includes:

- the correct character layout, start position, object table, collision paths,
  foreground/background deformation, animated art, palette behavior, water,
  music, and level events;
- traversal-critical objects, hazards, badniks, minibosses, bosses, capsules,
  signposts, and character-specific route gates;
- act-to-act, zone-to-zone, special-stage, bonus-stage, death, restart, and
  save/resume transitions used by the route;
- sidekick behavior where the selected team has a sidekick, without allowing
  sidekick defects to block or corrupt the main-character route;
- rewind-safe object and event ownership for gameplay state reachable during
  the route; and
- native 320x224 behavior plus the supported viewport/team compatibility
  contracts already advertised by `next`.

## Milestone 0 — Establish the release baseline

**Status:** required first

`next` contains repeated integrations from earlier `develop` snapshots, but its
current tip does not yet contain the latest `develop` test-session coordinator
and hook installer. Before route or architecture completion is judged:

- merge the current `develop` tip into `next` in an integration worktree;
- preserve `develop` as the authority for shared ROM-accuracy/runtime fixes and
  re-express `next` features on the resulting owners where necessary;
- record and classify the pre-merge `develop` and `next` red sets, then accept
  no merge-introduced regression against the union of the parents;
- restore the JDK 21 `tools/testing/test-session` certifying path on `next`;
- refresh the Mod API candidate snapshot only after resolving the merged
  production surface; and
- replace stale release claims with current suite, trace, and feature evidence.

Gate: `next` builds through the project wrapper, ordinary and structural-guard
sessions produce certifying manifests, and every remaining failure has an owner
and release disposition.

## Milestone 1 — Lock the game-policy architecture before Mod API publication

**Status:** planned; architectural direction approved

`GameModule` remains the composition and lifecycle root. The change introduces
a typed policy subtree rather than a superclass or a second competing root.

Target boundaries:

- Add an immutable `GamePolicies` aggregate for game-wide behavioral facts.
- Move `GameRules` ownership out of `PhysicsProvider`; camera, rings, objects,
  sidekicks, power-ups, and drowning rules are not children of physics.
- Keep narrow records such as `CollisionRules`, `CameraRules`, and `RingRules`
  as the consumers' dependencies rather than passing the entire aggregate.
- Separate audio behavioral rules from ROM-backed asset loading and stateful
  sound-driver construction. `GameAudioProfile.createSmpsLoader(Rom)` is a
  factory concern, even though the current profile also contains policy.
- Keep art, mappings, PLC/DPLC data, ROM offsets, registries, zone events,
  object-family behavior, and mutable session services with their existing
  smallest accurate providers or owners.
- Keep factories and lifecycle callbacks on module-owned runtime components;
  policies must be immutable and must not acquire session state.
- Support cross-game donation through explicit capability-specific composers.
  Do not add a generic mechanism that can arbitrarily replace any policy
  category.
- Preserve the rule-placement admission checklist and add guards against a new
  broad feature bag or game-name branches in shared runtime code.

This milestone must land before the first Mod API 0.7 baseline is published.
The candidate currently exposes gameplay policy types, so the migration must
update the recursive API inventory, creator documentation, sample mods, and
compatibility evidence together. Once a baseline is published, policy reshaping
must follow the published compatibility contract rather than silently rewriting
it.

Gate: all three stock modules expose the same typed policy shape; shared
consumers depend on their narrow category; supported donation combinations are
explicitly tested; invalid generic mixtures are not representable through a
public composer; and module/bootstrap, rewind, audio, trace, and Mod API guards
remain green.

## Milestone 2 — Complete the shared S3K campaign backbone

**Status:** partially landed on `next`

Close campaign-wide blockers before treating the character runs as independent
bug lists:

- finish level/event/runtime owners for SOZ, LRZ, HPZ, SSZ, DEZ, and DDZ;
- bring the existing FBZ implementation through its deferred complete-run,
  native squeeze-route, compatibility-matrix, and immutable visual gates;
- retain the landed MHZ route work, LBZ Big Arm port, super-emerald sanctuary,
  powered-form effects, and late-route object coverage under regression tests;
- complete all route-critical bosses, minibosses, prisons/capsules, transitions,
  and results handoffs;
- make chaos/super emerald, big-ring, special-stage, and bonus-stage round trips
  preserve the active character, team, save, audio, art-queue, and rewind state;
- finish S3K object art and dynamic loading through ROM-backed PLC/Kosinski
  owners; and
- resolve shared collision, object lifetime, sidekick CPU, camera, audio, and
  hardware-timing divergences at their ROM owners rather than per-route gates.

Gate: a clean save can progress through the common campaign graph, every
transition has focused headless coverage, and the first divergence in each
canonical character run belongs to character-specific work rather than a
missing shared level.

## Milestone 3 — Knuckles complete route

**Status:** substantial trace and super-emerald groundwork landed; route open

Complete Knuckles' alternate layouts, starts, traversal, bosses, and transitions
through both halves of the game. Particular attention belongs to character-only
paths, climbing/gliding collision, Knuckles-specific bosses and cutscenes, the
HPZ sanctuary flow, SSZ progression, and the Mecha Sonic finale.

Gate:

- one clean playthrough progresses AIZ to the Knuckles SSZ finale without
  debug intervention;
- the canonical complete-run movie replays end to end with no unexpected
  physics, animation, auxiliary-state, transition, or hardware-timing error;
- all chaos/super emerald detours represented by the canonical route return to
  the correct origin and preserve progression; and
- save/resume, death/restart, rewind, 320px rendering, and supported widescreen
  rendering do not alter the native route.

## Milestone 4 — Tails complete route

**Status:** shared-route and multi-sidekick work landed; route open

Complete Tails' solo movement and collision path, flight/swim exhaustion and
recovery, boss participation, late-zone traversal, and Death Egg conclusion.
The route must not inherit Sonic-only gates, assumptions about a main Sonic
player, or CPU-sidekick state when Tails is the selected main character.

Gate:

- one clean solo-Tails playthrough progresses AIZ through DEZ without debug
  intervention;
- the canonical complete-run movie replays end to end with no unexpected
  comparison error;
- flight, swimming, carry/interaction, damage, drowning, transformation, and
  route-specific collision have focused ROM-cited tests; and
- save/resume, death/restart, rewind, special/bonus-stage returns, and supported
  viewports preserve the same route outcome.

## Milestone 5 — Sonic complete route

**Status:** early/mid-game route and powered-form groundwork landed; route open

Complete Sonic's normal locked-on route through DEZ and the emerald-selected
DDZ branch. Preserve insta-shield, Super/Hyper state, late-game boss control,
emerald eligibility, and the transition from the Death Egg finale into Doomsday.

Gate:

- a normal route reaches the correct non-DDZ ending;
- an eligible emerald route enters and completes DDZ, then reaches the good
  ending;
- the canonical complete-run movie replays end to end with no unexpected
  comparison error; and
- save/resume, death/restart, rewind, transformation expiry, music restoration,
  and special/bonus-stage round trips preserve the selected ending branch.

## Milestone 6 — Complete all three outros

**Status:** planned

An outro is complete only when ordinary gameplay hands off naturally to it. It
includes the character-specific final encounter, ending cutscene, emerald-based
variant, music and sound-driver transitions, credits, post-credits scene or
result, and return to the appropriate title/data-select state.

Required matrix:

| Character | Required outcome |
|---|---|
| Knuckles | SSZ/Mecha Sonic handoff, Knuckles ending variants, credits, post-credits handoff |
| Tails | DEZ handoff, Tails ending variants, credits, post-credits handoff |
| Sonic | DEZ normal ending and emerald-selected DDZ/good ending, credits, post-credits handoff |

Gate: every matrix row has a headless lifecycle test, a deterministic visual
capture covering its important presentation phases, correct audio restoration
and shutdown, and a full input-driven route that reaches it without a direct
screen bootstrap.

## Milestone 7 — Graduate work already staged on `next`

**Status:** implemented in substantial part; release validation remains

The following are existing `next` workstreams and are part of the 0.7 candidate.
Their presence in branch history is not by itself a release claim.

### Modding and creator tooling

- Mod API 0.7 candidate, release-line policy, recursive signature inventory,
  trusted code mods, patch composition, music overrides, ROM-art intake,
  owner-tagged characters, custom/standalone games, tagged saves, and explicit
  gameplay policies.
- Deterministic `ggfmod` tooling, hardened Tiled TMX import, creator handbook,
  compatibility guide, and CI-built sample gallery.
- Editor object/ring placement, collision and solid-index editing, library
  panes, versioned saves, and full-level export foundations.

Gate: publish the first API baseline only after Milestones 0 and 1; build and
run every maintained sample; validate SDK/Javadoc packaging and native-image
constraints; keep the audited backlog's parked and dropped items out of the
release gate unless separately approved.

### Time Attack and multiplayer

- Solo Time Attack with curated tracks, deterministic input recordings,
  best-ghost racing, split deltas, instant retry, and Ed25519 player identity.
- Multiplayer race protocols, authenticated rooms, relay/ghost transport,
  standings, voting, spectating, minimap/nameplate presentation, and verified
  service foundations already present in `next` history.

Gate: local solo play remains deterministic and offline-safe; LAN and hosted
paths have bounded failure behavior and security review; no network or external
content is enabled during certifying trace/test sessions; service-dependent
features degrade honestly when services are unavailable.

### S3K, rendering, and compatibility foundations

- FBZ parity uplift, MHZ route work, LBZ late-route objects and Big Arm,
  super-emerald progression/sanctuary, Super Tails flock, and Hyper Sonic
  effects.
- Arbitrary-sidekick ownership work across S1, S2, and S3K, plus supported
  widescreen object/render boundaries.
- Live viewport capture, render-copy harnesses, allocation reductions, and
  S3K trace-parity improvements.

Gate: retain each advertised behavior under focused tests and visual evidence;
do not let compatibility or viewport support change native 320px timing; and
do not describe a partially gated zone or trace as complete.

## Milestone 8 — Release candidate and publication

**Status:** final gate

The 0.7 release candidate requires:

- JDK 21 ordinary and fresh-JVM structural-guard sessions with certifying run
  IDs, manifests, and logs;
- focused route, ending, Mod API, editor, Time Attack, multiplayer, rewind,
  audio, rendering, and native-image/package suites;
- canonical full-run trace evidence for Knuckles, Tails, and Sonic, with the
  command, commit, result, error count, and first error maintained in the trace
  frontier log until each reaches its terminal gate;
- input-driven headless smoke runs for every required ending outcome;
- deterministic visual captures for late-route transitions, bosses, and all
  three outros;
- no regression relative to the recorded integration baseline, including no
  worsened pre-existing red;
- final `README`, configuration, creator/player guide, known-discrepancy,
  detailed release ledger, public release summary, and changelog updates; and
- publication of the Mod API 0.7 baseline only after the candidate surface and
  migration guidance are final.

## Explicit non-goals

The following do not block 0.7 unless later evidence shows that they block one
of the outcomes above:

- arbitrary mixing of every policy category between games;
- replacing `GameModule` with an inheritance hierarchy;
- broad S1/S2 architecture migration unrelated to a release regression;
- every optional mod/editor item preserved in the deferred backlog;
- unsupported character/zone combinations not present in the shipped locked-on
  routes; and
- trace-specific gameplay corrections, fixture-fitted constants, or runtime
  asset fallbacks to the disassembly tree.

## Working order

1. Integrate and certify the current baseline.
2. Land the policy-root migration before freezing the Mod API surface.
3. Close shared late-game levels and transitions in route order.
4. Drive the Knuckles, Tails, and Sonic canonical runs independently while
   fixing shared causes once at their ROM owner.
5. Close the outro matrix.
6. Validate and document the existing `next` feature set.
7. Cut the release candidate only after the complete-run, regression, visual,
   packaging, and API-publication gates agree.
