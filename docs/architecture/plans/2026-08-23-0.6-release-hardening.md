# OpenGGF 0.6 Release Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the non-human release blockers that can be fixed without changing the documented human QA gate, while preserving ROM-derived gameplay behaviour and proving each correction with focused tests.

**Architecture:** Work in four independently testable slices: rewind-owned PLC state, test-service construction, trace-report publication, and release-gate evidence policy. Production gameplay changes are allowed only where a failing regression test identifies a state-ownership or restore defect; direct Mockito setup failures stay in test infrastructure.

**Tech Stack:** Java 21, Maven, JUnit 5, Mockito, Surefire, isolated `tools/testing/test-session.sh` runs, ROM-backed headless fixtures.

**Spec:** `docs/architecture/audits/release-architecture-review-issues.md` and the release gates in `.github/workflows/release.yml`.

## Global Constraints

- Build and test on JDK 21; use `mvn -v` to verify the Maven JVM.
- Runtime asset bytes remain ROM-only; no trace or disassembly data may hydrate gameplay state.
- Per-game differences stay in the existing provider/profile/registry owners.
- Every bug fix gets a failing JUnit 5 regression test before production code changes.
- All test output and native extraction remain inside `tools/testing/test-session.sh` sessions.
- Do not modify or stage the seven pre-existing S1 special-stage files in the main checkout.
- Do not use `--no-verify`; commits must carry the repository trailers.
