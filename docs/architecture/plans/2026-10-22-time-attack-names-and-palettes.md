# Time Attack international names and player palettes (2026-10-22)

## Outcome

Players can be named in any left-to-right script, choose that name when their identity
is first created, rename later without a new identity, and pick a look: a base colour
(their name colour) and a recoloured 16-entry character palette from presets or custom
Mega Drive colours. Others see the name in that colour above a ghost drawn in that
palette; the player's own character uses it too.

User decisions (2026-10-22): font option E (Fusion Pixel 10px proportional, GNU Unifont
fallback) chosen from a five-way mock-up; palette means a recoloured sprite palette, sent
as a delta from the ROM palette; left-to-right without shaping or bidirectional
reordering (Arabic/Hebrew/Indic shaping is a follow-up); the look applies to the local
character as well as ghosts. Names fade with their ghost, as nameplates already do.

## Contracts (committed first; lanes build on them)

- `NameFont` (`mods.ui`, `@ModApi`): 13-pixel line box, Fusion first, Unifont fallback
  aligned on the shared baseline, grapheme-safe `fit`, `extent` for tall fallback
  glyphs, visible placeholder for anything else. Fonts ship unmodified with OFL texts.
- `DisplayNames` (`net.identity`): NFC, single spaces, no controls/format/private-use/
  unassigned/bidi overrides, at most two marks per base, 20 code points and 64 UTF-8
  bytes. Clients send canonical names; hosts and the master reject anything else.
- `PlayerAppearance` (`net.identity`): base colour + strictly ascending palette entries
  in `0x0BGR` even-nibble colours; canonical wire string `BGR(.IBGR)*`, empty for stock.
- Protocol v4: `Hello.appearance` (signed transcript tag `client-auth/v2`);
  `UpdateProfile(displayName, appearance)` client to host in LOBBY; `PlayerLook(slot,
  appearance)` host to clients. Looks travel per player because `RoomState` must keep a
  256-player roster inside 64 KiB.
- `GhostPose.appearance` / `ActiveGhost.appearance`; stock keeps today's grey ghost.

## Risky assumptions

- Super/Hyper write the shared character line: private rows recompose from the live line
  and override only entries still equal to stock, so Super cycling still shows.
- 4 private rows per recoloured sprite against the 64-row cap: player + 8 ghosts = 36.
- SAT-masking zones draw no ghosts today; unchanged.
- IME preedit is not shown; committed code points from GLFW are typed.

### Rejected approaches

- **Fonts A–D** from the five-way mock-up (one GHZ still with the same fourteen names
  per option, 2026-10-22): A Fusion 12px + Unifont fallback and B Unifont alone at
  16px had no missing glyphs but taller, wider plates (B's 16-pixel line takes four
  rows for what E fits in three); C Fusion 12px alone and D Fusion 10px alone each
  left 12 glyphs missing (the Arabic, Devanagari and Thai samples). The user chose E,
  Fusion 10px with Unifont fallback: the most compact option with no missing glyphs in
  the sample (scripts that need shaping still draw unshaped).
- **Per-tile palette override in `PaletteReplay`** (substitute colours per drawn tile at
  replay time): rejected for batching cost; every recoloured sprite would break the
  sprite batch. Private palette rows keep the ordinary indexed path and batch normally.
- **Looks inside `RoomState`**: rejected because a 256-player roster with looks does not
  fit the 64 KiB control frame. Looks travel per player (`Hello`, `PlayerLook`).
- **Allowlisting `graphics -> net` / `sprites -> net` in the ArchUnit edge ratchet**
  (delivery guard failure): rejected. `net` imports nothing outside itself, so moving
  `PlayerAppearance` out of it was also rejected; the renderer takes plain colours instead.
