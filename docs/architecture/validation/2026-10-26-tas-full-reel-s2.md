Two presentation owners require explicit scoped attachments. MTZ's `LazyMappingHolder` normally reads a loaded level game; the collision-only fixture has none. The adapter lends the exact native mappings and matching detached MTZ tile art, then restores the holder's original mappings/attempted fields. Component views have a blank backdrop. Where the fixture lacks visual terrain, no substitute level or inferred geometry appears. Private fixture players need not be registered in `GameServices`; global `state.jsonl` player fields can consequently be null. Local snapshot guards use the actual fixture player regardless of that registration.

Acceptance covers Start edges, frozen object/player/RNG state, shifted capsule omission, bind/unbind/load/trace boundaries and rewind. Cross-game clock ownership makes scope high. The unresolved choice is which existing owner supplies every tick. Confidence high for the mismatch, medium for all shared consequences.
- `arz-endpoint-routine-add`: `Obj89_Main_KillBoss` (`s2.asm:65237`) writes routine 8; `Obj89_Main_Sub2_AtTarget` (`s2.asm:65070`) then adds 2. `Sonic2ARZBossInstance.java:370` assigns routine 4 at the endpoint instead. - `special-stage-live-work-cost`: native `SpecialStage` (`s2.asm:6677`) performs input-dependent object/sprite work between VInt waits, while `Sonic2SpecialStageLagModel.java:34` uses only frame, speed and segment. Use matched completed-loop/VInt measurements, object/sprite/transfer costs and rewindable deterministic accumulators, not a fitted jump predicate or trace-row gameplay hydration. Validate independent stages/routes and maintain the isolated hardware timing contract. A bounded approximation is HIGH; exact CPU/VDP per-interrupt accounting would be VERY_HIGH and a larger architecture project. The required fidelity remains a design question. Confidence high for absent dependence, medium for a bounded replacement, low for exact parity without new measurements.
