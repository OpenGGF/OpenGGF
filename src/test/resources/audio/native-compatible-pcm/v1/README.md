# Native-compatible PCM component vectors, v1

Consumer: `com.openggf.audio.synth.TestNativeCompatiblePcmOutput`.
Tier: **output stage on an identical write schedule**: FM and DAC through the
YM2612 pins, plus PSG bytes through GPGX's own PSG, at NTSC and 44.1 kHz. These
vectors do not qualify the MAME YM2612 core, production write scheduling, carry
state, any game window or rendered ending PCM; those remain open.

## Input

`strobes.csv` (sha256 `5a2f9d2117d76de76532c80c115879c053459b797e63c6f462b15a0d43a268fd`)
is the raw YM bus strobe schedule (`cycle,bus_port,value`, applied before YM
internal clock `cycle`) that the production `Ym2612Chip` presents for the fixed
synthetic FM + DAC stream in `NativeCompatiblePcmVectors` (194 strobes, 7,113
24-cycle frames). `psg_writes.csv` (sha256
`fb43a688c60003c2b57e5f81be298c81a362aa1db065eb792954bc310da28444`) lists the
25 PSG bytes of that stream with their absolute master clock. The session
presents each byte at the time of the chip's next YM clock. The test
re-derives both files and requires byte equality, so the vectors and the
engine run share one input.

## Native-source generator

The generator is `tools/audio/native-pcm/generate_vectors.sh`. It builds the
self-authored driver `gpgx_pcm_vectors.c` with `shared_stub/shared.h` and
`musl_sin.c`, then links Genesis Plus GX's own sources from an external
checkout. No GPGX `sound.c` or `system.c` text is in the repository: the driver
re-expresses their documented behaviour, cited by line.

Prerequisites, all external and supplied by path:
- A BizHawk source checkout at `427556b5ef3ac437eba754d90c5e7e9096c9a8df`. Its
  `waterbox/gpgx/Genesis-Plus-GX/core` is `<gpgx-core>`. `build` verifies by
  SHA-256 every file it uses: `sound/ym3438.c` `519d005b...7241b`, `ym3438.h`
  `8e60e35f...7cd189`, `blip_buf.c` `f807ee67...0fc80461`, `blip_buf.h`
  `367414a8...0428e`, `eq.c` `44567e07...d885d3`, `eq.h` `4f55824d...596955`,
  `psg.c` `8ce15359...b766700`, `psg.h` `a8a9d4dd...55eb8f3`. Full hashes are in
  the script.
- clang and objcopy.

What the driver does:
- It replays `strobes.csv` into `ym3438.c` in `ym3438_mode_ym2612` (BizHawk
  `Nuked_YM2612`): the held 24-cycle sum times 11, `fm_preamp` 100, and a buffer
  delta at `start + k * 42` inside each 3420 * 262 master-clock frame.
- It drives `psg.c` as GPGX's `sound.c` does: `psg_init(PSG_INTEGRATED)`,
  `psg_reset`, `psg_config(0, 150, 0xff)`, each `psg_write` at its in-frame
  master clock before that YM clock, and `psg_end_frame` before
  `blip_end_frame`.
- It reads every available sample at each frame end, then applies none,
  LowPass (`lp_range`, 16-bit carries) or ThreeBand (`eq.c`, 16-bit clipping).
- `eq.o`'s `sin` is renamed to `musl_sin`, because the BizHawk core links musl
  rather than the host glibc.

Commands (compiler and runtime leases per AGENTS.md):
`tools/audio/native-pcm/generate_vectors.sh build <gpgx-core> <build-dir>`, then
`tools/audio/native-pcm/generate_vectors.sh run <build-dir> src/test/resources/audio/native-compatible-pcm/v1 <out-dir>`.

## Equaliser `sin` from the actual native core

The stock BizHawk 2.11 core is `dll/gpgx.wbx.zst`, sha256
`c4231296ec5ba59b431df22b68e234ae7bfbbfc87b6e72fa471234ac1b220d12`. This is
the TraceChaser source-lock "stock" core. Its ELF decompresses to sha256
`b4cc6dabc069a6f1b87790212d80f665d216e603aa4990955cc816d5bf98d218` and is
not stripped. Its inlined `init_3band_state`, in `audio_reset`, calls musl's
`sin` at `0x36f00004e14`.

`tools/audio/native-pcm/stock_core_sin.c` maps that ELF's load segments at
their fixed addresses. The scratch original that produced the pinned dump had
sha256 `827b9393721c83821c5a23710fdaf263208e0ddbc9e768fe94bd2252e47735b8`;
the promoted copy differs only in its header comment. It executes the core's own
`sin` for every 16-bit cutoff at 44.1 kHz. The test pins the dump hash
`c2cc5844...cceeb8`, and `MuslSin` reproduces all 65,536 values.
`StrictMath.sin` differs on 792 of them. Host glibc gives a different
880 Hz cutoff: in an earlier harness build, that changed 916 of 11,774
unity-gain ThreeBand samples.

## Perturbations that must fail

A one-unit pin-sum change, a one-clock (42 master clocks) origin shift, one
flipped PSG data bit and one PSG level write moved a quarter NTSC frame later
each break `native-none`. Small moves can be invisible by construction: a
one-YM-clock move of a frequency write, and a 960-clock move of that level
write, both were. GPGX applies PSG effects on 240-clock steps, and a level
change on a low channel waits for the next flip. Mid gain 1.01, a low cutoff of 881 Hz and the no-filter
output break `native-threeband-unity`. `lp_range + 1` breaks
`native-lowpass-6666`.
